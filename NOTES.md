# Teaching Notes

## How the user learns
- **Project-driven**: tie every lesson to real code/work the user is doing now. Ask for a concrete example to apply the idea to.
- **Reading-heavy**: each lesson should recommend a high-trust primary source; lessons reinforce the reading rather than replace it.
- Short, frequent lessons. One tangible win each. Respect small working memory.

## Calibration
- Early-career (0–3 yrs) but ambitious — chose to start with the *hardest* strategic muscle (system/codebase design). Watch the ZPD gap: keep design lessons grounded in concrete code, not abstract architecture.
- Small-team / startup context. Decisions have near-term consequences; "influence" is real.
- Sharp self-awareness about the AI-era thesis (AI eats tactical work; strategic skills are the remaining leverage). Don't re-sell the premise — they already believe it. Build on it.
