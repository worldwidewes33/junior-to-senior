# Baseline established: early-career engineer pursuing strategic judgment in the AI era

The learner is early-career (0–3 yrs) on a small team / startup, and explicitly arrived already holding the mission's premise: AI is eating tactical coding, so the strategic skills (design, planning, judgment, directing AI) that used to mark the junior→senior leap are now table stakes. I did **not** need to sell that thesis — build on it, don't re-argue it.

They chose to start with the *hardest* strategic muscle, **system & codebase design**, despite being early-career. This is an ambitious ZPD gap. Mitigation in effect: teach design strictly through concrete code and the lens of *managing complexity* (Ousterhout), never abstract architecture/patterns. Watch for the lesson floating above real code — pull it back down if it does.

Learns best **project-driven** + **reading-heavy**: every lesson must anchor to real work and recommend a high-trust primary source. No real codebase example captured yet — Lesson 01 ends by asking them to bring a shallow module from their own code; that becomes the anchor for Lesson 02.

Planned sequence after design foundations: information hiding → planning & decomposition → technical judgment/tradeoffs → directing AI as a force multiplier.
